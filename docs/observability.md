# Observability

The `wxyc_fastapi.observability` module ships three coupled concerns: cache stats (per-request metric dict in a ContextVar), the PostHog client wrapper, and request telemetry that drives the per-step PostHog events. Sentry init lives in the same module but is documented inline in the public-API section of [`architecture.md`](architecture.md#public-api-surface).

## Cache stats: behavior recap

`init_cache_stats` seeds the per-request stats dict with six base keys (`memory_hits`, `pg_hits`, `pg_misses`, `api_calls`, `pg_time_ms`, `api_time_ms`); `extra_keys=[...]` adds consumer-specific metrics. `extra_keys` is a *shape guarantee* — it makes sure the named keys appear in `get_cache_stats()` with value `0` even when never recorded, so PostHog event shapes stay stable across requests. It is not a permission system: `recorder.record(key, value)` and the named helpers (e.g. `record_memory_cache_miss`) will create undeclared keys on first call.

`CacheStatsRecorder` exposes well-named helpers (`record_memory_cache_hit`, `record_pg_cache_miss`, `record_pg_time(ms)`, ...) plus a generic `record(key, value)` for ad-hoc metrics. All recorder methods are no-ops when `init_cache_stats()` has not been called for the current async context, so library code can call them unconditionally.

## PostHog wrapper

`get_posthog_client(event_prefix)` returns a lazy singleton. The `event_prefix` argument is purely diagnostic — it surfaces in the warn-once log line that fires when `POSTHOG_API_KEY` is missing, so co-located services each get one warning instead of one per call. The returned client is shared across callers; events are **not** auto-prefixed.

The `posthog` SDK is imported inside `get_posthog_client` on first successful call (when an API key is set). Consumers that never call it do not need the `[posthog]` extra installed — semantic-index relies on this.

Unless disabled, the returned client is a token-bucket **capture rate limiter** (v1.4.0) around the SDK client, sized by `POSTHOG_RATELIMIT_EVENTS_PER_MINUTE` (default 60, sustained) and `POSTHOG_RATELIMIT_BURST` (default 1800, bucket capacity); env vars are read once, at first client construction. `POSTHOG_RATELIMIT_EVENTS_PER_MINUTE=0` disables wrapping entirely (raw SDK client returned); non-numeric and non-finite values (`nan` would silently defeat every guard, `inf` would pin the bucket full) fall back to the defaults with a warning, and a burst in (0, 1) — which would permanently drop every capture, since admission needs a whole token — clamps to 1. Only explicit `capture` calls are gated — feature-flag reads, `flush`, `shutdown`, and `capture_exception` delegate untouched (exceptions bill under PostHog error tracking's separate quota). Two caveats on that boundary: the SDK's own `$feature_flag_called` emission happens inside the inner client, *below* the proxy, so flag reads still produce billable events the limiter never sees (gating every SDK-internal emission path needs a `before_send` hook — tracked separately); and attribute *writes* such as the SDK's `client.disabled = True` kill switch forward to the inner client, so runtime toggles behave as documented instead of shadowing on the proxy.

`POSTHOG_RATELIMIT_EXEMPT_EVENTS` (comma-separated exact event names) bypasses the bucket for hand-picked counters that feed alerts and must survive exactly the saturation windows that trip the limiter (e.g. a fail-open counter). An exempt event is unbounded again — keep the list short and each entry inherently low-rate.

Dropped captures batch into at most one `telemetry_rate_limited` event per minute, carrying `dropped_count`, `sample_events` (up to 5 distinct dropped names), `limit_events_per_minute`, `burst`, and `trigger_distinct_id`, emitted under the stable identity `wxyc-fastapi-ratelimiter` so alerts can key on it. The first drop after a quiet stretch reports immediately; a pending tail is drained by the next admitted capture past the report interval and force-drained by `flush`/`shutdown`, so a flood that simply ends is still accounted for. Every report also logs at WARNING. The limiter is a per-process circuit breaker for runaway instrumentation — the 2026-08-04 org-wide quota cutoff — not a budget enforcer: an N-worker deploy admits N× the configured rate (tune the env down per worker, e.g. LML's three), and legitimate bulk work that trips it should aggregate to per-run summary events rather than raise the limit.

## PostHog errors client and logging handler

`get_posthog_errors_client()` (`observability/errors.py`) returns a singleton `PosthogErrorsClient` keyed by `POSTHOG_ERRORS_API_KEY`, or `None` when unset — so a service can send errors to a different PostHog project than its analytics. `PosthogErrorsHandler(client)` is the `logging.Handler` that replaces Sentry's `LoggingIntegration` ("ERROR is alertable"): attach it to the root logger when the client is non-`None`.

- **With `exc_info`:** forwarded to the SDK's `capture_exception`.
- **Without it:** the SDK's `capture_exception` returns nothing when no exception is active, so the client sends a synthesized `$exception` event instead — `$exception_list` holds one entry (type = logger name, value = `record.getMessage()`, `mechanism = {handled: true, type: "logging"}`) and `$exception_fingerprint = f"{record.name}:{record.msg}"` — one string, because PostHog types the field `Option<String>` and drops an event that sends a list. The unformatted template groups by call site. Limitation: a call site that pre-formats its message (`logger.error(f"failed for {name}")`) has a different template per value, so it neither groups nor dedupes; use `%s` arguments.
- **Backstop:** one token bucket (`ERRORS_EVENTS_PER_MINUTE`, `ERRORS_BURST`) and a same-fingerprint dedupe window (`ERRORS_DEDUPE_WINDOW_SECONDS`) gate both paths in the client; deduped repeats cost no token. Per-process, like the analytics limiter. The dedupe table is bounded. Dropped records are counted and logged as one WARNING at most once a minute.
- **Re-entrancy:** records from the `posthog` and `wxyc_fastapi.observability` logger trees are ignored (other package loggers such as `wxyc_fastapi.healthcheck` are reported), as are records logged on the same thread while a capture is in flight.
- Frame locals (`capture_exception_code_variables`, posthog>=6.9) are off.

## Testing helpers

`wxyc_fastapi.testing` (v1.4.0) ships `CountingPosthog` — an in-memory client stand-in that records every `capture` as a `CapturedEvent(event, distinct_id, properties)` and no-ops `flush`/`shutdown` — and `capture_budget(max_events, client=None)`, a context manager that yields a `CountingPosthog` and fails the test with the captured event names when the block records more than `max_events`. Budget the hot paths in consumer suites: one lookup/request should emit at most one summary event, and a bulk job over N items should emit O(1) events per run, not O(N). The helpers need no `posthog` install, so they work in suites that stub the client everywhere.

Fidelity: `CountingPosthog.capture` mirrors the posthog 7.x signature the consumers pin (`capture(event, *, distinct_id=..., properties=...)`), so the legacy `capture("uid", "event")` two-positional form raises `TypeError` — the real 7.x SDK logs-and-discards that call, and a budget test must fail loudly rather than certify telemetry production would drop. `capture_exception` records a `$exception` event; `feature_enabled`/`get_feature_flag` resolve to `None` and record nothing. For call sites annotated `Posthog | None`, wrap the fake in `as_posthog(...)` (a zero-cost `typing.cast`) to satisfy mypy.

## Telemetry

`RequestTelemetry(api_call_keys, distinct_id, event_prefix, emit_step_events=True)` tracks step timings + per-service API-call counts for a single request. The `event_prefix` namespaces the emitted PostHog events: `lookup` produces `lookup_<step>` per-step events and a `lookup_completed` summary; `request` produces `request_<step>` and `request_completed`.

`emit_step_events` (v1.3.0, default `True`, keyword-only) gates the per-step events: set it `False` to emit **only** the `<prefix>_completed` summary. No *timing* data is lost — the summary's `steps` property already carries every per-step timing (`{<step>_ms: <duration>}`); the only fields dropped are the per-step `success`/`error_type` (a failed step's error is not surfaced in the summary), so suppress only where those per-step fields are themselves unconsumed. This is for high-volume consumers whose per-step events are unconsumed: LML's `/lookup` registers ~9 `track_step` legs, so the default fans one lookup out to ~10 PostHog events; a Backend-Service backfill campaign (2026-08-01) multiplied ingestion ~7× accordingly, for events no insight or alert reads. Consumers that *do* build dashboards on per-step events (request-o-matic's "Average Duration by Step") keep the default. The toggle is per-`RequestTelemetry`, so a consumer can suppress on one route (LML `/lookup`) while leaving others (`streaming_check`, `artist_resolve`) at the default.

`track_step` is a context manager that records duration even when the body raises (it re-raises after stamping `error_type`). `send_to_posthog` reads cache stats from `cache_stats.get_cache_stats()` so telemetry and cache-recording stay decoupled — consumers initialize cache stats and telemetry independently per request.

`as_server_timing(extra=None, descriptions=None)` (v1.1.0, `descriptions` added in v1.2.0) serializes the **same** already-captured `track_step` durations to a [`Server-Timing`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Server-Timing) response-header value — a second surface for the step timings, not a second capture. It emits `<name>;dur=<ms>` per tracked step (insertion order), then one entry per `extra` item (durations measured *outside* `track_step` — e.g. LML's derived `discogs` = `pg_time_ms + api_time_ms`, or request-o-matic's forwarded LML sub-stages), then exactly one live `total` from `get_total_duration_ms()`, `", "`-joined. Because the method always appends its own canonical `total`, `extra` must not carry a `total` key (the request-o-matic merge strips the forwarded LML `total` first) or the header carries two. The header `total` is sampled a few milliseconds before `send_to_posthog`'s `total_duration_ms` — independent measurements, not identical. Handlers inject a Starlette `Response` and set `http_response.headers["Server-Timing"]` after finalizing their body; the durations-only header adds no data-sensitivity concern.

`descriptions={leg_name: text}` is a strictly opt-in map — any tracked-step name, `extra` key, or `"total"` — that upgrades a leg from `name;dur=<ms>` to `name;desc="<sanitized>";dur=<ms>`. It exists for legs that are derived or overlapping rather than additive, so summing every `dur` in the header would double-count: LML's `discogs` leg is the motivating case, since it re-measures time already reflected in another span. Text is passed through `_sanitize_desc` first. A `desc` value is RFC 7230 `quoted-string` content embedded in a header the consumer serializes with `.encode("latin-1")`, so it is coerced to a printable-ASCII whitelist (`0x20`-`0x7e`): every non-ASCII code point and C0/C1/DEL control character is dropped, which guarantees the value survives the latin-1 encode instead of raising `UnicodeEncodeError` (a blacklist that missed any code point above U+00FF — an accented letter, CJK, an emoji, U+2028/U+2029 — would not). From the surviving printable-ASCII set the header's own structural delimiters `,` (entry separator), `;` (param separator), and `=` are stripped (a downstream parser like request-o-matic's `parse_server_timing` splits on bare `,`/`;` with no notion of "inside a quoted string", so escaping wouldn't help; `=` is dropped as defense-in-depth against a parser that scans for `dur=` anywhere in an entry), while `"` and `\` are escaped (`\"`, `\\`) since they remain legal quoted-string content once escaped. A leg whose description sanitizes to nothing falls back to the plain `dur`-only form. Names not present in `steps`/`extra`/`"total"` are silently ignored, and omitting `descriptions` (or passing only `extra`, as every pre-1.2.0 caller does) produces byte-identical output to before.
